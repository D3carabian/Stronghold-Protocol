## 本地开发

使用 Node.js >=22.13 或 24、Git 和 Python 3.11+。`npm ci` 安装依赖，`npm run dev` 启动上游开发服务器。
开发服务器没有网站准入门禁，保持只监听本机：`HOST=127.0.0.1 npm run dev`。

`npm run ci` 运行上游检查；`npm run golden` 检查玩法结果；
`python3 -m unittest discover -s ops -p 'test_*.py'` 检查部署和资源工具。
素材缺失时测试可能跳过，需要资源的端到端检查另做，不能把跳过计为通过。

## 目录与修改边界

`server/`、`shared/`、`public/`、`tools/` 保持上游结构。新增运维代码在 `ops/`，说明在 `docs/fork/`，
跨会话执行计划规则在根目录 `PLANS.md`，AI 工作约定在 `AGENTS.md`。本机生成物只放 `.local/`。
不要提交访问密码、SMTP 密钥、服务器数据、游戏资源或本机绝对路径。上游文档仍以其自己的设计与忠实原则为准。

改动使用 `feature/...`、`fix/...` 或 `update/v...` 分支；PR 目标始终是本 fork 的 `main`，避免误发到上游。
无需将 `main` 强制同步成上游；上游新版本必须合并并测试。修复应尽量小，附复现和证据。

## 当前产品边界

已交付两套可运行的游戏环境、更新基础工具和邮箱准入模块。
邮箱验证＋邀请码的代码和部署支持已实现，实际启用情况见 STATUS.md；后台、随机控制、历史战绩与完整自动发布仍在路线图中。
